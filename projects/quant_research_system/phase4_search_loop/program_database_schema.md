# Phase 4 Program Database Schema

## Purpose

The program database is the search-facing memory for the AlphaEvolve-style loop.

It is not the official candidate registry. It stores all generated programs, including invalid, repaired, rejected, near-miss, and successful candidates, because those records drive future parent and inspiration sampling.

## Storage Decision

```yaml
program_database:
  primary: SQLite
  audit_log: JSONL append-only
  large_metric_panels: Parquet when available; CSV fallback allowed
  analysis_reporting: DuckDB when available; SQLite/pandas fallback allowed
```

SQLite is chosen because it requires no external server and is available through Python's standard library. This is compatible with the remote-server constraint that external `.exe` installs cannot be assumed.

## File Layout

```text
artifacts/phase4_alphaevolve/program_database.sqlite
artifacts/phase4_alphaevolve/audit_log.jsonl
artifacts/phase4_alphaevolve/metric_panels/
artifacts/phase4/<run_id>/evaluator_summary.json
artifacts/phase4/<run_id>/prompt_card.md
artifacts/phase4/<run_id>/failure_report.md
```

The implementation modules live under `research/alphaevolve_lite/`, but runtime database files are artifacts. They should not be committed as source files. Local development may use a temporary smoke-test database under `artifacts/local_smoke/`.

## IDs

```yaml
id_formats:
  program_id: "PROG-{YYYYMMDD}-{six_digit_counter}"
  prompt_id: "PROMPT-{YYYYMMDD}-{six_digit_counter}"
  run_id: "RUN-{YYYYMMDD}-{six_digit_counter}"
  branch_id: "BRANCH-{root_candidate_id}-{three_digit_counter}"
  split_id: "daily_stock_top500_chrono_70_15_15_v1"
```

IDs must be generated by the controller, not by the LLM.

## Audit Log

Every material event must append one JSON object to:

```text
artifacts/phase4_alphaevolve/audit_log.jsonl
```

Required event types:

```yaml

  - seed_inserted
  - prompt_built
  - llm_response_received

  - patch_applied

  - remote_sample_eval_completed
  - remote_validation_started
  - remote_validation_completed

  - map_cell_updated
  - candidate_promoted
```

## Required Query API

Codex should implement these functions before large-scale search:

```python
insert_program(record) -> str
insert_prompt(record) -> str
insert_evaluation(record) -> str
append_audit_event(event) -> None
sample_parent(island, mode, rng) -> ProgramRecord
sample_inspirations(parent, k, rng) -> list[ProgramRecord]
update_map_cell(program_id) -> None
get_validation_exposure(root_candidate_id, branch_id, split_id) -> dict
increment_validation_exposure(...) -> None
get_prompt_card(program_id) -> dict
```

## Data Integrity Requirements

- Every program must have a hash.
- Every generated child must have a parent.
- Every prompt must list inspiration program IDs.
- Every evaluation must point to an artifact directory.
- Every remote-validated program must have an `evaluator_summary.json`.
- A test-evaluated program must have `branch_frozen = true` before test evaluation.
- No test metrics may be included in prompt context for future mutation.
